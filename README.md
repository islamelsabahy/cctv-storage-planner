# cctv-storage-planner

[![CI](https://github.com/islamelsabahy/cctv-storage-planner/actions/workflows/ci.yml/badge.svg)](https://github.com/islamelsabahy/cctv-storage-planner/actions/workflows/ci.yml)

**EN** — Size the storage and network for a CCTV system: give it camera groups (count, resolution, codec, fps, recording hours) plus the retention you need, and it returns the stream bandwidth, GB written per day, how many disks you need for your RAID level, and how many days those disks really hold. Two front ends share one set of formulas: a Python CLI/library (no dependencies) and a bilingual single-page calculator in [`docs/`](docs/index.html) that works offline and can be served with GitHub Pages.

**AR** — حاسبة لتخطيط التخزين والشبكة لنظام الكاميرات: اديها مجموعات الكاميرات (العدد، الدقة، الترميز، عدد الإطارات، ساعات التسجيل) ومدة الاحتفاظ المطلوبة، وهي تطلعلك سرعة البث، والـ GB اللي بيتكتب يوميا، وعدد الهاردات المناسب لنوع الـ RAID، وعدد الأيام اللي هتكفيها فعلا. فيها سكريبت بايثون وصفحة ويب بالعربي والإنجليزي بتشتغل أوفلاين بنفس المعادلات.

> **Planning estimates, not guarantees.** Default bitrates are conservative planning figures (H.264, 25 fps, medium quality). Real bitrates depend on the scene, lighting, and camera settings. If you can, record a day on one camera, read its actual bitrate and pass it as a measured value (for example `4x3000k`).
>
> **أرقام تقديرية للتخطيط وليست ضمانا.** معدلات البت الافتراضية محافظة؛ الأفضل تقيس معدل البت الفعلي لكاميرا حقيقية وتدخله.

## Use / الاستخدام

```bash
python -m cctvplan --camera 16x4mp:h265:15 --camera 4x8mp:h265:12 --days 30 --disk-tb 8 --raid raid5
```

```text
Cameras: 20   Stream total: 41.29 Mbps (plan the network for ~51.61 Mbps)
  16 x 4mp: 1843.2 kbps each, 19.91 GB/day each
  4 x 8mp: 2949.1 kbps each, 31.85 GB/day each
Writes per day: 445.91 GB
Need 14.86 TB usable for 30 days (incl. 10% reserve)
=> 3 x 8 TB disks in RAID5: 24.0 TB raw, 16.0 TB after RAID, holds 32 days
```

Camera spec: `COUNTxRES:CODEC:FPS[:HOURS[:ACTIVITY]][:audio]`. Repeat `--camera` for every type you have; each group has its own count, resolution, codec, fps, hours and audio setting.

| Part | Values |
|---|---|
| `RES` | `1mp 2mp 4mp 5mp 8mp`, or a measured bitrate like `3000k` |
| `CODEC` | `h264`, `h265` (half the bitrate), `h265plus` (35%) |
| `HOURS` | recording hours per day (default 24) |
| `ACTIVITY` | share of those hours with footage, e.g. `0.3` for motion-only (default 1) |
| `audio` | optional flag: adds 64 kbps per camera in that group |

Mixed fleet (10 plain 2MP, 6 two-megapixel with audio, 8 four-megapixel with audio):

```bash
python -m cctvplan --camera 10x2mp:h265:15 --camera 6x2mp:h265:15:audio --camera 8x4mp:h265:15:audio --days 30
```

The web calculator does the same with *Add camera group*, *Duplicate* and a *With audio* checkbox per group.

Other options: `--raid none|raid0|raid1|raid5|raid6|raid10`, `--disks N` (report retention for a fixed disk count), `--reserve 0.10`, `--json`.

```python
from cctvplan import plan
plan([{"count": 16, "resolution": "4mp", "codec": "h265", "fps": 15}], retention_days=30, disk_tb=8, raid="raid5")
```

Web calculator: open `docs/index.html`, or enable GitHub Pages for the `docs/` folder.

## How it is calculated / طريقة الحساب

- Bitrate = table value for the resolution × codec factor × fps ÷ 25, plus 64 kbps with audio.
- GB per day = kbps × 1000 ÷ 8 × recorded seconds × activity ÷ 10⁹ (decimal GB, like disk vendors).
- Required usable space = GB per day × days ÷ (1 − reserve). The default 10% reserve covers file-system overhead and overwrite margin.
- Disks: the smallest count whose capacity after RAID (RAID 5: n−1, RAID 6: n−2, RAID 1/10: half) covers that space.
- Network figure adds 25% headroom over the summed stream bitrates.

## Tests

```bash
python -m unittest discover -s tests -v   # hand-checked maths, RAID rules, CLI
node tests/test_planner.js                # browser formulas vs the shared vectors
```

`tests/vectors.json` holds ten scenarios generated by the Python reference. The Python tests check the maths against hand calculations; the Node test proves the web page gives identical results to Python.

## Limits / حدود

- Ignores overhead from audio codecs, metadata, event clips, and variable-bitrate peaks.
- Does not model NVR channel or throughput limits: check the recorder's specification separately.
- Disk sizes are decimal TB as sold, not TiB.
